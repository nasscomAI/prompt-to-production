**Did the naive prompt add any information not in the source document (scope bleed)?**

## How to Reproduce Both Runs

```bash
cd uc-0b

# the failure
python app.py --input ../data/policy-documents/policy_hr_leave.txt \
              --output summary_naive.txt --mode naive
# → RESULT: FAIL — 13 missing clauses, 1 condition drop, 5 banned phrases

# the fix
python app.py --input ../data/policy-documents/policy_hr_leave.txt \
              --output summary_hr_leave.txt
# → RESULT: PASS
```

Both paths are scored by the same `validate_summary`, so the difference between
them is measured rather than asserted. The enforced path exits non-zero if
validation fails, so a broken summary cannot be written out and mistaken for a
finished one. `validate_summary` also runs standalone against a summary produced
by any other tool, which is how you would test whether a different model's output
drops clauses.

## CRAFT Loop Reflection

**Which CRAFT step was hardest across all UCs, and why?**

> Analysing the output honestly. It is very easy to read the naive summary, see
> fluent well-organised prose about leave policy, and tick it off as fine — nothing
> in it is *false*, and the failures are all absences. Clause 2.5 does not announce
> that it is missing. The only way to catch it was to build the ground-truth clause
> inventory first and diff against it mechanically, which is why the validator got
> written before the summariser was trusted.

**What is the single most important thing you added manually to an agents.md that the AI did not generate on its own?**

> The verbatim fallback, and the reasoning behind it:
>
> > *"REFUSAL / VERBATIM FALLBACK: If a clause cannot be rendered without losing a
> > critical token, the summariser must not paraphrase it. It must emit the source
> > text verbatim, mark the block [FLAG: VERBATIM-REQUIRED …]. Refusing to compress
> > is always preferred to compressing lossily."*
>
> Every draft the model produced treated "summarise" as an unconditional instruction
> — the job was to make it shorter, and shorter is what it delivered. The rule that
> changed the behaviour was the one that made *not compressing* an allowed outcome.
> The same reasoning drove the design note in `agents.md`: obligation wording is not
> paraphrased at all, because "preserve all conditions" cannot be mechanically
> verified across an arbitrary paraphrase. The register is scannable because of its
> structure — clause IDs, named binding verbs, enumerated conditions, approver
> markers — not because the obligations were shortened. That is a deliberate trade
> of brevity for verifiability, and for a compliance document it is the right way
> round.
